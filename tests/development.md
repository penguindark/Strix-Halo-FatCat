# tests — development.md

## Goal
Correctness assurance: unit tests for parsers and kernels, and numerical
correctness tests of the forward pass against reference implementations
(HuggingFace transformers / llama.cpp on small slices).

## Status
**P0 + P1 suites (2026-11-02).** All plain C binaries registered with CTest:
- `test_gguf.c` (`gguf_reader`): synthetic GGUF v3 builder covering all
  KV types (incl. string arrays and the 1-byte bool), quant tensor sizing
  (Q4_K, IQ1_S), name lookup, data integrity, single-file and llama.cpp-style
  split GGUF, garbage rejection. Note: build type defines NDEBUG, so tests
  use their own always-on `CHECK()` macro, never `assert()`.
- `test_dequant.c` (`dequant_kernels`): scalar dequant F32/F16/Q8_0/Q6_K/
  IQ2_XXS/IQ1_S **bit-exact vs gguf-py golden data** (`tests/data/
  dequant_golden.bin`, generated by gguf-py — the golden reference).
- `gputest.c` (`gpu_kernels`): per-quant-type GPU vs CPU GEMV on real model
  tensors, pass at ~1.2e-7 norm-relerr; skips cleanly when no GPU.
- End-to-end numerical check vs llama.cpp lives in `tools/` (`llama-ref.cpp`
  + `expert-profiler --check`): full-model logits corr 0.997, top-1000 ≥931.

## Scope
- In: unit tests (GGUF parser, dequant round-trips, router top-k, streaming
  policy simulator), golden-output tests for layers, memory-safety runs
  (ASan/UBSan builds).
- Out: model quality evaluation (kept in `benchmarks/`).
